# Фильтр вкладок креатива (creative_tab.py)

Основание: пустые клетки во вкладках «Regions Unexplored», «Perfectplushies», «Mcwholidays» и др. (скриншоты владельца) и статический аудит `creative-tab-audit.md` (304 кандидата на пустую иконку при 10 340 записях).

## Сделано

`tools/creative_tab.py` больше не кладёт во вкладку все объявления `horizon/item` и `horizon/block`. Запись остаётся в вкладке, только если у неё есть работающая иконка:

- **Нет `assets/<ns>/items/<id>.json`**: скрывается (посевы, технические блоки, настенные варианты без предмета).
- **Нет геометрии у модели предмета.** Цепочка родителей собирается целиком (текстуры потомка перекрывают родительские, `#alias` раскрывается, циклы обнаруживаются). Нужны либо `faces`, либо слой `layerN` у `builtin/generated`. Скрываются: нет модели или родителя, цикл, битый JSON, пустой узел, «голый» `builtin/entity` (плюшевые игрушки без рендерера).
- **Настенный двойник** скрывается только при наличии объявленной пары в том же namespace: `wall_X → X`, `X_wall_sign → X_sign`, `X_wall_hanging_sign → X_hanging_sign`, `X_wall_deco[_N] → X`. Самостоятельные `*wall*` без пары остаются.
- **Иконка вкладки** выбирается из оставшихся записей (запись с именем namespace, иначе первая). Нет ни одной записи: вкладка не создаётся и заголовок не пишется.
- Нельзя доказать пустоту: оставляется. Это custom-loader, `minecraft:special`, условные узлы с рабочей веткой, а также родитель из `minecraft:` при отсутствии корня ресурсов. Отсутствующая текстура не скрывает запись (её надо чинить, а не прятать).
- Скрытые ID остаются зарегистрированными: миры, рецепты и теги не ломаются. Скрывается только вкладка.
- **Заголовок вкладки** берётся из `name` в `horizon-mod.toml`, если `id` равен namespace (было `ns.capitalize()`: «Mcwholidays», «Perfectplushies»; теперь «Macaw's Holidays», «Perfect Plushies»). Уже существующий `itemGroup.<ns>` не перезаписывается.
- Новые параметры: `--resources <dir>` (корень ванильных ресурсов; по умолчанию `work/homestead-horizon/runtime-01/resources`, если есть), `--no-resources`, `--assets <dir>` (другие моды для межмодовых ссылок), `--list` (печать скрытых ID с причиной). В конце печатается строка вида `Wrote N creative tab(s); left out of tabs: M (no_item=…, no_geometry=…, wall_pair=…)`.
- `tools/hide_unplaceable.py`: если иконка вкладки попала в скрытые лодки, она перевыбирается из оставшихся (раньше оставалась на скрытой записи, например `regions_unexplored:baobab_boat`).
- `tools/creative_tab_checks.py`: 10 групп проверок на синтетических каталогах (`python -I creative_tab_checks.py`).

Пересобраны (скриптами проекта, без игры и cargo): все 45 архивов `horizon.3` (`Build-DataMods.ps1`), шесть архивов batch1 (`Build-Batch1.ps1`), шесть batch2 (`Build-DataMods-batch2.ps1`), Farmer's Delight `horizon.10` (`Build-FarmersDelight.ps1`).

## Отличается от оригинала

В оригинальных модах (Java) эти предметы либо имеют рендерер предмета (плюшевые игрушки через BEWLR), либо вообще не являются предметами (посевы, настенные блоки). У таких плюшевых игрушек в Horizon нет рендерера предмета: модель — голый `builtin/entity`, по аудиту слот пуст (в игре не проверено). Поэтому они скрыты из вкладки, но остаются зарегистрированными, рецепты не удалялись. Рендерер плюшевых игрушек не реализован.

## Не проверено

- Игра не запускалась: что слоты теперь не пустые и что перелистывание не лагает, не подтверждено. Лаг разобран отдельно (`creative-lag.md`), этот фильтр уменьшает число записей, но не его причину (первое запекание моделей).
- Остаются 28 записей с `missing_texture` (bakery 7, regions_unexplored 7, suppsquared 5, candlelight 4, ends_delight 3, perfectplushies 1, expandeddelight 1): они не скрыты, показываются заглушкой missing-texture; текстуры нужно чинить отдельно. Часть ссылок идёт на ресурсы других модов или Create-JAR вне `.hmod`.
- Аудит статический: прозрачность PNG, transforms и ветки условных моделей не проверяются.
- `Build-Batch1.ps1` после упаковки архивов упал на шаге датапака SparseStructures: нет `-Mcmeta` (скрипт ищет `outputs/homestead-horizon-stage19|18|17/datapacks`, а их в рабочей копии уже нет). Архивы batch1 собраны полностью, датапак в `pack-batch1/datapacks/homestead-sparse` не менялся. Для штатной пересборки нужно передать `-Mcmeta` из пакета stage22.
- Архивы в `stage4/extra-mods` пересобраны, но `runtime/game/horizon-mods` и пакет stage22 содержат старые копии; в игре и в пакете изменение появится после следующих `Prepare-Candidate`/`Build-Package`. Приёмка `-DataMods` и `-Batch1/-Batch2/-FdStage23` на новых архивах не прогонялась (она запускает игру).
