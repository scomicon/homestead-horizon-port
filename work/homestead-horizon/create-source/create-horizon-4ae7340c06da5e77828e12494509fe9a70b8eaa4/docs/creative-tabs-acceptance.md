# stage23: сценарий игровой проверки вкладок креатива

## Сделано

Добавлен `ST/acceptance/Test-HomesteadCreativeTabs.ps1`. Файл ASCII, требует PowerShell 7, как `Test-HomesteadClientDefaults.ps1`. При подготовке сценарий **не исполнялся**, клиент, сборка и тесты не запускались. Общие файлы не изменены. Подключение описано в `mixins/homestead/fragments/creative-tabs-acceptance.md`.

Сценарий подключается к **уже запущенному** одноразовому клиенту через `horizon-ctl --socket`. Он сверяет параметры с `ST/runtime/current-run.json`, PID и путь работающего бинарника, записывает SHA-256 бинарника, самого сценария и четырёх архивов. Рабочая папка допустима только внутри `ST/runtime/`; junction/symlink в её предках отклоняется. Мир должен иметь префикс `HomesteadAutomation`. Сценарий требует режим креатива и начальный экран `playing`, не открывает другой мир, не запускает второй клиент и не меняет режим игры.

### Вкладки и первые 45 слотов

Проверяются следующие namespace (названия вкладок после исправления генератора могут отличаться от скриншотов):

| Скриншот / мод | Namespace |
| --- | --- |
| Mcwholidays / Macaw's Holidays | `mcwholidays` |
| Regions Unexplored | `regions_unexplored` |
| Perfectplushies / Perfect Plushies | `perfectplushies` |
| Perfect Homestead Plushies | `phomesteadplushies` |

Ожидаемый порядок предметов берётся из `data/<ns>/horizon/creative_tab/*.json` в **установленных** `GameDir/horizon-mods/*.hmod`, а не из старого отчёта аудита. Несколько деклараций одного целевого namespace считаются ошибкой. В текущем клиенте заголовки вкладок и номера их страниц не входят в `ui`, поэтому сценарий использует `click-at` и геометрию из `creative.rs` / `game/creative_screen.rs`: панель 195×136 GUI-пикселей, колонки с шагом 27, верхние/нижние кнопки, стрелки над панелью. Начало панели вычисляется из `ui.gui_size` с усечением, как `HudBatch::centered_origin`. Переходы ожидают новый `ui.frame`. Предельное число страниц задаёт `MaxTabPages` (по умолчанию 16); если цель не найдена, успех не записывается.

Для каждой цели `ui` возвращает слоты `slot-900`…`slot-944`. Их ID и порядок точно сверяются с первыми 45 записями декларации; последующие пустые позиции допустимы, если **всего** в списке меньше 45 предметов. Например, вкладка после удаления невидимых моделей может содержать 33 записи и 12 свободных клеток. Это отличается от пустой иконки у существующего стека. `null` среди ожидаемых предметов, другой ID или пропущенная позиция — ошибка.

Сохраняется PNG первого экрана каждой вкладки. **Наличие стека не доказывает видимую иконку**: `ui_control.rs::node_value` возвращает `stack_value`, где есть ID/количество/компоненты, но нет результата запекания модели и признака видимых пикселей. Поэтому `icons_status` остаётся `not_verified`. Автоматического сравнения цвета клетки нет: подсветка, полупрозрачные модели и фон дали бы ложные результаты.

### Холодная и тёплая прокрутка

Метод следует гипотезе из [creative-lag.md](creative-lag.md): модели лениво запекаются при первом показе. Для каждой вкладки сразу после снимка первых слотов выполняются два прохода **сверху вниз по одной строке**:

1. `cold_first_traversal`: первый обход ранее не показанных рядов в данном сценарии.
2. Возврат наверх, вне измеряемого окна, затем `warm_repeat_traversal` по тому же маршруту.

Перед каждым проходом вызывается `stats reset`, после — `stats raw`. Число шагов равно `max(0, ceil(item_count / 9) - 5)`. На каждом шаге `scroll-at X Y -1` выполняется над полосой прокрутки (без наведения на предмет); сценарий ждёт новый кадр и сверяет все 45 ID с ожидаемым смещением `row * 9`. Таким образом, неподвижная сетка не выдаётся за прокрутку. Стрелки страниц вкладок не используются вместо прокрутки предметов. Ограничение `MaxScrollRows` (по умолчанию 512) при превышении вызывает ошибку, а не усечённый успешный замер.

В JSON сохраняются числовые `frames`, `seconds`, `p50_ms`, `p95_ms`, `p99_ms`, другие поля сводки клиента и массивы `frame_ms`, `cpu_ms`, `gpu_ms`, а также длительность прохода `elapsed_ms`. Максимальный кадр можно получить из `frame_ms`; CPU/GPU сводки сохраняются в исходной форме. Отсутствие кадров, неполный массив или некорректные значения делают сценарий красным. Вкладка до 45 предметов получает `not_applicable`, `rows: 0`, `stats: null`: прокрутки в ней нет и нулевые миллисекунды не выдумываются.

Измеряемое окно содержит кадры между командами, задержки запуска ctl и чтения `ui`. Это характеристика управляемого обхода, **не задержка одного события колеса**. Начальное открытие вкладки и снимок экрана в замер не входят. Первые 45 моделей к этому моменту уже показаны. Навигация по страницам тоже может показать первые ряды других вкладок; предложенный фоновый разогрев может дополнительно запечь модели. Поэтому `cache_cold_verified: false` сохраняется даже для холодного прохода. Сценарий не очищает кэши клиента, файловой системы или драйвера. Для более строгого сравнения нужен свежий процесс на каждый мод и отдельная телеметрия кэша.

Одинаковые настройки, бинарник, архивы, разрешение, GUI scale, VSync/лимит FPS, фоновая нагрузка и патч разогрева должны сохраняться при сравнении до/после. Скрипт не устанавливает порог производительности и не объявляет лаг исправленным по одному проходу.

### Purple Ornament Wall Deco 2

Настенный вариант `mcwholidays:purple_ornament_wall_deco_2` может быть скрыт из вкладки как дубль. Поэтому отсутствие его в сетке **не считается** проверкой исправления подсказки. После всех замеров сценарий выбирает свободный слот хотбара, выдаёт туда точный ID через `item replace`, проверяет `inventory.held.item` и вызывает существующую команду `homestead tooltip show` (`mixins/homestead/client_tooltips.rs`). Эта команда получает `game.stack_tooltip` на клиентском потоке, включая нативные хуки.

Текстовая проверка выполняется только при `options-get lang` = `en_us`: требуется единственный ответ с префиксом `homestead tooltip lines: Purple Ornament Wall Deco 2`. В нём запрещены `When on Head` и `Waypoint Transmit Range`. Пустой ответ, неоднозначные строки чата, другая локаль или отсутствие свободного слота дают `not_verified`, а не успех. Ошибка выдачи ID или запрещённая строка дают провал. Существующие стеки не перезаписываются, тестовый предмет убирается, первоначальный слот и экран `playing` восстанавливаются. Ошибка восстановления отражается отдельно и запрещает успех автоматической части.

Проверяется текст подсказки предмета в руке. Текст при наведении на сетку креатива использует дополнительные флаги, а изображение подсказки сокет не возвращает: это отдельная визуальная проверка.

### Квитанция

Файл в одноразовом `GameDir`: `stage23-creative-tabs-creativetabs-result.json`. Снимки имеют имена `stage23-creative-tabs-<run_id>-<namespace>-first45.png`; старые снимки не принимаются за новые. Предыдущая квитанция заменяется на `passed: false` до подключения к сокету. Внутри есть `run_id`, UTC-время, хэши, проверки, результаты четырёх вкладок, подсказка и `not_verified`. Полные локальные пути, имена игрока и сырой вывод ошибок в квитанцию не копируются.

`automation_passed: true` означает только успешную сверку стеков, выполненные/неприменимые замеры и проверенный текст подсказки. **`passed` остаётся `false`, `status: not_verified`, и сценарий завершает работу ошибкой**, пока нет проверки видимых иконок. При реальном сбое `status: failed`. Это намеренно не позволяет существующему runner принять частичную проверку как полную приёмку. Не менять `passed` вручную; визуальные свидетельства следует оформлять отдельным этапом приёмки.

Будущий запуск (сейчас не выполнялся): после единоличного запуска клиента через `Start-Test.ps1` с `HOMESTEAD_WINDOWED=1` прочитать `runtime/current-run.json` и передать его `socket`, `game`, `world`, `process_id`, а также `candidate/client/horizon-ctl.exe` в параметры `-Ctl`, `-Socket`, `-GameDir`, `-World`, `-GameProcessId`. Скрипт сам игру не закрывает: обычные `save`/`quit` и ожидание выхода принадлежат runner, включая случай неполной приёмки.

## Отличается от оригинала

Это регрессионный сценарий Horizon, а не сравнение с Java-клиентом. Проверяется фактически установленный отфильтрованный список, поэтому скрытые настенные пары и служебные варианты не обязаны присутствовать. Сценарий фиксирует диагностические числа и ограничения доступного сокета; он не устанавливает визуальную паритетность с оригинальными модами.

## Не проверено

- Исполнение нового PowerShell-сценария и реальные ответы клиентского сокета на этом бинарнике. Выполнена только статическая проверка текста/синтаксиса.
- Видимые иконки всех ожидаемых предметов первых 45 слотов, включая очень маленькие/полупрозрачные модели; названия и иконки кнопок вкладок.
- Наведение на Purple Ornament Wall Deco 2, внешний вид подсказки и локализации кроме условия английской текстовой проверки.
- Фактические холодные/тёплые времена кадров, причина рывков и эффект предложенного патча разогрева. Чисел до запуска нет.

Для визуального этапа просмотреть PNG каждой вкладки и сопоставить занятые позиции с `first_45_ids`: пустые строки в конце — допустимое заполнение, пустая картинка на непустом ID — дефект. Проверить также нижнюю часть длинных вкладок и наведение на предмет из жалобы в отдельной ручной сессии. Текущие скриншоты пользователя показывают старые дефекты и не служат подтверждением исправления.
