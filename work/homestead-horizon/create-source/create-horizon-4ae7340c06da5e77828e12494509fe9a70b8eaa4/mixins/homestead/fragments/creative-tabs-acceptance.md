## Run-Acceptance.ps1

Будущие правки интегратора, все ветки согласовать в одном изменении:

1. В `param(...)` добавить `[switch] $CreativeTabs`.
2. В условие установки `HOMESTEAD_WINDOWED` до вызова `Start-Test.ps1` добавить `-or $CreativeTabs`. Аудио не требуется. Использовать свежий процесс, не запускать другой набор до нормального завершения этого клиента.
3. В начало выбора `$reportName` добавить ветку `if ($CreativeTabs) {'run-creativetabs-result.json'}`; прежний первый `if` станет `elseif`.
4. В выбор `$runs` добавить перед остальными наборами:

```powershell
if ($CreativeTabs) {
    $runs=@(,@((Join-Path $PSScriptRoot 'acceptance/Test-HomesteadCreativeTabs.ps1'),'CreativeTabs','stage23-creative-tabs-'))
} elseif (...) {
    # Existing branches remain here.
}
```

Префикс и имя фазы дают `stage23-creative-tabs-creativetabs-result.json`, совпадающее со сценарием. Параметры `Ctl`, `Socket`, `GameDir`, `World`, `GameProcessId`, `Phase` уже передаются циклом runner. Нельзя принимать только `automation_passed`: пока иконки не проверены, сценарий сохраняет `passed: false` и бросает исключение. Runner обязан записать красную/неполную квитанцию и выполнить свой `finally` с обычным `quit` и ожиданием завершения процесса. Не добавлять waiver или преобразование неполного результата в зелёный.

## regress.ps1

```powershell

```

До этого запускать `-CreativeTabs` отдельно для диагностики: текущая неполная визуальная проверка намеренно даёт красный результат и не должна незаметно попасть в обязательную регрессию как зелёная. Не включать набор в разрешающий список `Build-Package.ps1` без отдельного решения интегратора о полноте свидетельств. Ни этот документ, ни успешная автоматическая часть не разрешают упаковку при непроверенных иконках.
